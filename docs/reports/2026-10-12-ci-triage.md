## Class (d), in full

### 1. `tinto/words` "a slow face": the board is laid before its face has arrived

**What it looked like.** The gate holds the Noto Sans Kannada request for 2 s and samples every frame. The board must not be laid while the face is missing. In CI, and in WSL in all three engines: 69 of 132 frames laid early. On Windows it passes. A timeline run in WSL: lines present (5 lines at 25.66 px) with the face not yet loaded, then the face arriving afterwards. The final size is the same, so the harm is a wrongly laid board for the time the face is on its way (the `loadingdone` handler lays it again).

**The cause.** The type tier's `fontReady(font, text)` awaits `document.fonts.load(font, text)`. The stacks in `packages/type/stacks.js` name a metric-matched fallback, `'Kalam Fallback'`, whose only source is `local('Segoe Print')` (`packages/tokens/fonts.css`), with no unicode-range. Only Windows has that font. On any other machine that face fails at once, and `load()` rejects as soon as one matching face fails, while the others are still being fetched. `fontReady` swallowed the rejection and returned. Reproduced in isolation: `fonts.load('400 20px KF, NK', 'ಕನ್ನಡ')` rejected with NetworkError after 4 ms with `KF:error NK:loading`; `fonts.ready` then resolved after 1523 ms, once NK had finished.

**Who it affects.** Every Mac, Linux and Android visitor with a slow Kannada or Devanagari face. The same line (`await document.fonts.load(...)` with a swallowed catch) sits in the bubble's first lay-out, which is why the bubble's "floats removed" control flapped: its "before" measurement was taken on a layout made in the fallback.

**The fix.** After a rejection, wait for `document.fonts.ready` (whatever failed for good is measured in its fallback). `packages/type/index.js` (`fontReady`) and `packages/components/bubble/skins/body.js`. New unit test `packages/type/fontready.test.js`; I ran it against the old `index.js` and it fails there. The Tinto control (`words.check.mjs`, "a build that neither waits for the face nor lays out again") would otherwise have been protected by the new wait and stopped being able to fail, so it now also strips that wait from `type/index.js`. Result in WSL: Chromium, Firefox and WebKit all pass the gate, and Windows Chromium passes.

**Not fixed, a risk.** The same `.then(redraw, () => {})` shape is in `chai`, `kairi`, `ghat`, `prahar`, `tinto/render`, `date-range`, `signature` and `greeting-card`. A label drawn once and never repainted would stay in the fallback on a Mac or Linux machine. I tried to see it (freeze, hash the canvas, force a redraw) but the page differs after a redraw on Windows too, so the instrument said nothing. Unverified.

### 2. WebKit on Linux: the 2D focus rack does nothing

**What it looked like.** `depth-photo`, quiet register (the 2D tier): `plate sharpness 1334 -> 1334`, so "Focus on the plate" sharpens nothing. Warm and playful (live tier) pass.

**The cause.** The 2D tier decides whether to use the canvas filter by writing `ctx.filter = 'blur(2px)'` and reading it back. WebKit keeps the string and draws the picture sharp. Reproduced: a 40 px black/white edge drawn through `blur(4px)` reads 0 at x=18 and 255 at x=20, no gradient.

**The fix, and its limit.** `canFilter` (`packages/stage3d/depth-photo/depth-photo.2d.js`) now draws a hard edge through the filter and looks at the edge pixel's alpha. It is 245 bytes; the registry's JS budget for the piece had 267 left. With the probe correct, WebKit falls back to the down-and-up scale, which is too weak: sharpness goes 588 to 1330, 2.3 times, against the 5 times the check asks for. A cascade of halvings made it worse (881) and was reverted. So this red remains until the fallback blurs for real (repeated offset draws, or an SVG filter, would be the next things to try). The scenes that blur with `ctx.filter` (`dar`, `ferry`, `kantar`, `khazan`, `mosaico`, `nod`, `tollem`, `toran`) are also sharp there, and nothing checks it. Not in the known-flake table: it fails every time, which is not a flake.

## What I fixed, and how

- **CI.** `ci.yml`: every browser shard installs its own engine and Chromium (cache key and both install commands).
- **Locale.** `localeEnv()` in `tools/lib/engine.mjs` (with a unit test) returns the environment with `LC_ALL=en_IN`; `wa-order` and `food-order` launch with it. Both Chromium and Firefox read it with no locale files installed (checked; `LANG`, `LC_ALL` and, for Chromium, `LANGUAGE` all work, `--lang` does not).
- **Glass baseline.** The core as it stood at 654935d is `tools/fixtures/tinto-glass/scene-element.main-654935d.js`, 16,835 bytes, read with `readFileSync`.
- **WebKit start-up.** `export.check.mjs` passes its switches through `launchArgs`.
- **Textarea ceiling.** `grow-press.check.mjs` measures against 20em of the textarea's own font plus its padding and border (`+1`), not an assumed 16 px. No looser than before.
- **The Firefox JS-off hang.** Two causes in `waitReady` (`tools/lib/browser.mjs`): `document.fonts.ready` never settles on a page whose JavaScript is off, and `setTimeout` inside such a page never fires. A no-JS page is now waited for from the harness, bounded (5 s and 2 s). depth-photo in Firefox: killed at 600 s before, 16 of 16 pass with 6 skipped in 45 s after. BROWSERS.md had this down as "runs past 15 minutes".
- **Fixed waits became state waits.** `menu` (ends the strip on the finished animation), `action-menu` (waits for `aria-expanded="false"`; the component is unchanged, see below), `core/csp` (waits up to 8 s for the grip), `tabs` (waits for the selection to move), `bubble` (waits for the arrival to finish, then watches a second more so a later flash is still seen).
- **The action-menu race.** After Escape, the popover stops matching `:popover-open` a task before its `toggle` event reaches the component, which still believes it is open. An ArrowDown in that gap moves focus inside a closed menu. No person presses that fast, so I changed the check, not the component. If someone wants it tight, `#onTriggerKey` could read `matches(':popover-open')` instead of `#open`.
- **Registry** rebuilt (type, bubble, depth-photo changed); `docs/BROWSERS.md` has a new section under "CI on Linux".

## Follow-up after Rasika's review (13 October 2026)

- **Chromium-only checks are skipped, not passed, under another engine.** `tools/checks.mjs` prints `skip  <check>  (drives Chromium itself; --engine=<e> does not reach it)` for any check whose source matches `/chromium\.launch\(|scene-probe/` when the engine is not Chromium. They count as neither a pass nor a red, and the summary line says how many were skipped. `tools/lib/chromium-only.core.test.mjs` scans the repo for them and fails if the list changes without `docs/BROWSERS.md`. The Chromium install stays on every shard. The `tabs` row above is corrected (it is a Chromium check). The 20 files are listed in BROWSERS.md as Chromium-only until they launch the requested engine.
- **action-menu.** `#onTriggerKey` asks `this.native.matches(':popover-open')`, not the `toggle`-event mirror `#open`. A new clause calls `hidePopover()` and dispatches ArrowDown in one task: red on the old component (`{"open":false,"focus":"account-trigger"}`), green on the new one (`{"open":true,"focus":"mi-profile"}`), with a control that proves the gap is real.
- **fonts.ready has a ceiling.** `fontReady` and the bubble's first lay-out race `fonts.ready` against 4 s (`FONT_WAIT_MS`), longer than the Tinto slow-face gate's 2 s hold. `fontready.test.js` has a case where `ready` never settles. The Tinto control strips the race as well, so it still fails when it should.
- **The Tinto control is required in Firefox** (`!== 'webkit'`, for both the label and the condition).
