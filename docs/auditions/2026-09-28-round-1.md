# Audition round 1: "build a café site with Susegad"

*Sutradhar, 28 September 2026. Library at `main` `4d94868`, before the open-the-door batch. This is the baseline. Round 2 runs the same brief after that batch merges.*

## Setup

- **Brief:** a one-page static site for a fictional Aldona bakery-café, Bebinca & Co.
  - Requirements: a hero scene, six menu items in rupees, opening hours, WhatsApp and email (placeholders), and a visitor-facing register switch.
  - Rules: the library's CLI must be used, no build step, no external requests, WCAG 2.2 AA in every register and scheme, 390px wide, reduced motion.
  - The model writes a `NOTES.md` on what confused it.
  - Brief, runner and grader: `C:\Users\schan\susegad-auditions\` (`r1/BRIEF.md`, `run-one.sh`, `grade.mjs`).
- **Harness:** `opencode run` 1.18.31, headless, with `--auto` and a 45-minute cap, three candidates in parallel.
  - Each candidate got a fresh clone of the library, outside `C:\Projects`, so no workspace AGENTS.md reached it.
  - **Contamination found and removed:** by default opencode loads `~/.claude/CLAUDE.md` into every session. It was proved with a probe ("GitNexus: MANDATORY" came back) and disabled with `OPENCODE_DISABLE_CLAUDE_CODE=1` and an empty `XDG_CONFIG_HOME`.
  - **Residual:** the descriptions of the owner's global skills (gitnexus, officecli) are still listed to every candidate, identically.
- **Grader:** Playwright plus axe.
  - Gates:
    - the site exists
    - it used the CLI (the lockfile is present)
    - the library clone is untouched
    - it loads cleanly (no console errors, failed requests or external requests)
    - the hero scene draws (canvas or SVG, more than 100px wide)
    - the brief's content is there
    - the page's own controls reach all three `data-register` values
    - axe with WCAG 2.2 AA tags, 3 registers × 2 schemes, under reduced motion, run twice with only repeated violations counted
    - no horizontal scroll at 390px
    - the scene holds still under reduced motion
  - **Validated on both sides:** it failed a deliberately broken site on 6 gates.
  - **Grader bugs found and fixed:** SVG scenes (vel) were scored as not drawn; the hours regex was too strict; a "3 or more pieces" gate wasn't in the brief; one axe run was flaky under load.

## What the models told us (their NOTES.md, several independently)

1. **SKILL.md's inventory was stale.** It named 3 scenes where there are 27, and 20 components where there are 31. *Fixed on `batch/open-the-door`:* the inventory is now generated from the registry, with a `--check`.
2. **Scenes didn't say what they're for.** Only vel's description did ("for heroes…"), so 5 of 8 heroes were vel, and MiniMax used a UI-sketch sheet as a hero. *Fixed on the door branch:* a `useFor` field on every scene.
3. **The CLI's hint after `add` gave paths from the repo root**, not the web root. *Fixed:* `--base`.
4. **There's no register switcher to reach for.** Every model hand-built one, and one built it wrong. → a `sg-register-switch` component, as with `sg-sound-switch`.
5. **There's no layout guidance** (page container, gutters). Two sites put content flush against the viewport edge. → a layout primitive or recipe, plus a skill note.
6. **Agents hang on dev servers.** Three runs hit the cap because a server never exited. → ship `susegad verify <dir>`: serve, check (axe, 390px, console, reduced motion) and exit. The grader is already most of it.
7. **Library bugs reported, to verify:**
   - The playful `site-nav`'s rotated tabs overflow by about 2px and cause horizontal scroll (DeepSeek).
   - The pause button still shows under reduced motion in warm and playful (DeepSeek).
   - `reach` pulls in the whole `stamp` package (a known registry-granularity issue).
